# SECURITY.md — NLAMS Data Protection & Security

## Overview

NLAMS handles sensitive land acquisition data including Aadhaar numbers, bank account details, and personal information of Indian citizens. This document describes the data protection measures implemented in the system and how they map to India's Digital Personal Data Protection Act (DPDP Act) obligations.

## Data Classification & Protection

### Encrypted Fields (Fernet symmetric encryption)

These fields are encrypted at rest using Fernet (AES-128-CBC) with a key from the `ENCRYPTION_KEY` environment variable:

| Field | Table | Description |
|-------|-------|-------------|
| `aadhaar_masked` | `land_owners` | Aadhaar number (stored encrypted, displayed masked as `XXXX-XXXX-NNNN`) |
| `bank_account_masked` | `land_owners` | Bank account number (stored encrypted, displayed masked) |

**Encryption key management:**
- In production: `ENCRYPTION_KEY` env var is mandatory (Fernet key format)
- In development: Auto-generated ephemeral key with warning log
- Key rotation: Generate new key, decrypt all data with old key, re-encrypt with new key, update env var

### Masked-Only Fields (no encryption)

These fields are stored as plain text but masked in API responses:

| Field | Table | Masking Pattern |
|-------|-------|-----------------|
| `aadhaar_masked` | `land_owners` | `XXXX-XXXX-NNNN` |
| `bank_account_masked` | `land_owners` | `XXXX-XXXX-NNNN` |
| `phone` | `users` | Stored as-is (required for auth) |
| `ifsc` | `land_owners` | Stored as-is (not considered sensitive) |

### Access Control

| Data | Citizen | District Officer | State Authority | Super Admin |
|------|---------|-----------------|-----------------|-------------|
| Own Aadhaar/bank | ✅ Full | ❌ Masked | ❌ Masked | ❌ Masked |
| Others' Aadhaar/bank | ❌ Hidden | ❌ Masked | ❌ Masked | ❌ Masked |
| Audit log access | ❌ | Own actions | State-level | Full |

**All reads of sensitive owner data** (bank details, Aadhaar) are captured in the audit log with:
- `entity_type`: "land_owner"
- `entity_id`: Owner UUID
- `action`: "read"
- `performed_by`: Requesting user UUID
- `timestamp`: Auto-generated by ORM

## Audit Logging

Every write operation (create, update, delete) and every read of sensitive data includes an audit log entry in the `audit_logs` table with:
- Actor (user UUID)
- Timestamp
- Entity type and ID
- Action performed
- Old and new values (for writes)

## DPDP Act Compliance Mapping

| DPDP Obligation | NLAMS Implementation |
|-----------------|---------------------|
| **Data Minimization** (§5(2)(f)) | Only essential fields collected; Aadhaar stored as masked (last 4 digits); bank details stored masked |
| **Purpose Limitation** (§5(2)(a)) | Data used only for land acquisition lifecycle; no secondary processing |
| **Security Safeguards** (§8(1)) | Fernet encryption at rest; role-based access control; JWT authentication with refresh token rotation |
| **Access Logging** (§8(1)(d)) | Complete audit trail for all data access; sensitive field reads logged with actor + timestamp |
| **Data Retention** (§8(1)(f)) | Soft-delete pattern; data retained only for active projects |
| **Breach Notification** (§8(6)) | Structured logging with request IDs; Sentry error tracking (configurable) |

## Authentication Security

- **Password hashing**: bcrypt with automatic salting
- **JWT tokens**: HS256, short-lived access tokens (60 min), refresh tokens (7 days)
- **Refresh token rotation**: Each use issues a new token, old is revoked
- **Token revocation**: Logout revokes single token; logout-all revokes all user tokens
- **Rate limiting**: 5 attempts/min on login, 3 attempts/min on forgot-password
- **CORS**: Configurable via `CORS_ORIGINS` env var; production requires explicit domain listing

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `SECRET_KEY` | Yes (production) | JWT signing key |
| `ENCRYPTION_KEY` | Yes (production) | Fernet key for field encryption |
| `CORS_ORIGINS` | Yes (production) | Allowed frontend origins |
| `SENTRY_DSN` | No | Error tracking endpoint |
